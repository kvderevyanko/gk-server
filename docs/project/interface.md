# Интерфейс и пользовательские сценарии

## Назначение

Интерфейс — локальная панель управления домом. Обычный пользователь должен
понимать состояние устройства и результат команды без знания GPIO-пинов,
HTTP-endpoint'ов или структуры SQLite.

## Структура

| Раздел | Задача пользователя | Содержимое |
|---|---|---|
| Обзор | Быстро управлять домом | Избранные устройства, последние DHT-измерения, GPIO- и PWM-действия |
| Устройство | Управлять одним ESP | Переключатели, датчики и периферия выбранного устройства |
| Настройки | Настраивать систему | Технические CRUD-экраны устройств, пинов, PWM, WS и DHT |

Основной layout использует адаптивную боковую навигацию. На малом экране она
открывается кнопкой меню; в разметке есть skip-link для перехода к содержимому.
В боковой навигации остаются повседневные разделы и единый вход «Настройки».
Настройки открываются отдельным центром с карточками устройств, GPIO, PWM,
DHT, WS2812 и параметров панели; так технические CRUD не конкурируют с
ежедневным управлением.
Внутри этого центра перечень устройств использует карточки с явным состоянием,
ссылками только на включённую периферию и разделёнными действиями «Открыть
управление» и «Изменить». Табличные CRUD и формы наследуют те же цвета,
размеры полей и адаптивную прокрутку, поэтому остаются пригодными на телефоне.

## Обзор

Карточка избранного устройства показывает число активных GPIO и DHT, а также
открывает страницу устройства. Открытие карточки не выполняет сетевую проверку
или команду ESP: пока система не хранит подтверждённый status доставки, она
честно обозначает связь как непроверенную.

Для DHT выводится последнее сохранённое измерение температуры, влажности и его
время. Страница обзора читает только SQLite и не запускает опрос датчиков.
Если измерений нет, пользователь видит это явно и может перейти на страницу
устройства для обновления.

## Карточка GPIO

Карточка показывает устройство, имя переключателя, номер пина и выбранное
состояние. Toggle остаётся нативным checkbox, поэтому доступен с клавиатуры и
экранному диктору. Зона касания не меньше 44 px.

После действия пользователь видит один из статусов:

| Статус | Значение |
|---|---|
| `Отправляем…` | Браузер ожидает ответ Yii2 |
| `Включено` / `Выключено` | ESP подтвердил команду |
| `Не подтверждено` | Значение сохранено как желаемое, но доставка на ESP не подтверждена |

Интерфейс не повторяет GPIO-команду автоматически: повтор может быть опасен
для реле и моторов. Оператор принимает решение о следующей попытке сам.

## Доступность и визуальные правила

- CSS-токены задают поверхность, текст, границы, акцент и статусы;
- поддерживается системная светлая и тёмная тема;
- `prefers-reduced-motion` отключает декоративные анимации;
- фокус отображается явно, динамический статус передаётся через `aria-live`;
- имена устройств и настроек экранируются перед выводом.

## Границы текущей реализации

Новая оболочка, обзор устройств, DHT summary и карточки GPIO уже реализованы.
На странице устройства DHT использует отдельную адаптивную карточку: показывает
последнее сохранённое измерение, обновляет его только по явному нажатию и
открывает график истории без ухода со страницы. Во время запроса и при ошибке
доставки состояние сообщается в карточке; автоматических повторов нет.
PWM реализован новой карточкой с доступным range-control, числовым значением и
статусом доставки после отпускания ползунка. При отсутствии PWM-параметров
ползунок заблокирован и ведёт к их созданию. WS пока не выводится на
обзор, но на странице устройства уже перенесён в адаптивную карточку с
параметрами эффекта, выбором цвета и статусом доставки. Значение отправляется
только после завершения действия пользователя, без автоматических повторов.
Аутентификация и роли ещё не
реализованы: UI не следует считать защитой доступа к физическим устройствам.
