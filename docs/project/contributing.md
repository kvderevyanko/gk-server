# Вклад, проверка и документация

## Критерий готовности

Изменение готово, когда код проверен в соответствии с риском, документация
отражает фактическое поведение, а локальные данные и секреты не попали в Git.
Не отправляйте тестовые команды на живые ESP без отдельного согласования.

## Что обновлять вместе с кодом

| Изменение | Обязательная документация |
|---|---|
| Маршрут, JSON, HTTP-метод, ESP-протокол | `architecture.md` |
| Миграция, модель, данные SQLite | `architecture.md`, `operations.md` |
| Docker, `.env.example`, Make, запуск | `development.md`, `operations.md` |
| UI, сценарий, состояния, accessibility | `interface.md` |
| Известный риск или его устранение | `risks.md` |
| Цель или последовательность работ | `roadmap.md` |

Новый документ добавляют в `docs/project/README.md`. Устаревшие материалы в
`docs/system/` не меняют вместо актуальной документации без сверки с кодом.

## Локальная проверка

```bash
make lint
make init
make up
curl --fail http://127.0.0.1:8080/
```

`make up` не запускает scheduler. Полный контур — только явной командой
`make up-all`; перед ним нужно убедиться, что не работает дублирующий cron на
хосте и что запуск не затронет действующие устройства.
