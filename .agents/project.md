# Контекст проекта ESP Home

Это Yii2-приложение для управления ESP8266/NodeMCU в локальной сети. Корень
репозитория содержит PHP-код, Lua-прошивки, SQLite-миграции, Docker Compose и
техническую документацию.

## Инварианты

- Состояние локальных устройств в SQLite является рабочими данными: перед
  миграциями, обновлением образа или удалением данных нужна проверенная backup.
- Production запускается через `compose.yaml`; web и scheduler используют общие
  persistent-каталоги `db/`, `runtime/` и `web/assets/`.
- После развёртывания нового кода на действующий локальный сервер обязательно
  пересобрать и пересоздать Compose-сервисы командой `docker compose up -d
  --build`, затем проверить `docker compose ps` и HTTP-ответ. Одного `git pull`
  или restart недостаточно: исходники входят в Docker-образ.
- Команды к ESP способны менять физическое оборудование. Не посылать тестовые
  команды на действующие устройства без явного согласования задачи.
- Данные хоста, адреса, SSH-настройки, секреты и реальное `.env` остаются только
  в игнорируемой `.local/` или в окружении развёртывания.

## Источники истины

- `docs/project/` — поддерживаемая документация; старый `docs/system/` сверять
  с кодом.
- Код и миграции определяют фактическое поведение при расхождении документов.
- Роли для делегирования находятся в `.agents/roles/`.

## Документация как часть готовности

Каждое изменение должно в этой же задаче обновить соответствующий документ в
`docs/project/`. Это относится к пользовательскому интерфейсу, маршрутам и
контрактам, моделям и миграциям, Docker/Make, фоновым задачам, безопасности и
эксплуатации. Если подходящего документа нет, его создают и добавляют в индекс
`docs/project/README.md`. Перед завершением задачи сверяют документацию с
изменённым кодом и `git diff`.

Документация фиксирует только проверенное общее поведение. Локальные адреса,
учётные данные, ключи, токены, пути хоста и содержимое рабочей SQLite не
попадают в отслеживаемые файлы.

## Базовые проверки

Для PHP-изменений выполнить `php -l` затронутых файлов; для изменения
зависимостей — `composer validate`; для Docker — собрать образ и проверить
Compose. После появления тестового контура запускать относящиеся к задаче тесты.
